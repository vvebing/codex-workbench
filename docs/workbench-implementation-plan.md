## 分工与集成

按用户要求使用 GPT-6.1 Sol 子代理：A 负责草稿；B 负责权限；C/D 负责待办和通知队列。主代理负责 E/F、文档、代码审阅和总体验证。共享文件由负责人协调，禁止覆盖其他任务的修改，不提交或重置现有工作区。

持久化只保存业务草稿，不保存认证凭据。恢复数据经过校验、大小限制和版本判断；图片采用明确的可恢复策略，不能静默丢失。服务端历史仍是发送状态依据，不能以恢复记录推断请求未发送。

## 后续阶段（继续实施）

1. **结果交付面板**：整合已有总结、轮次 diff、仓库状态和代码审查入口。验证证据来自命令退出码与日志，分别标记通过、失败和未执行；不把模型结论直接当作测试结果。验收：一次任务结束后可从同一入口检查本轮变更与验证证据，且明确区分仓库其他修改。
2. **项目空间与验证命令**：项目保存目录、说明、显式配置和常用测试/构建命令；命令通过当前版本支持的执行接口运行，展示进程、退出状态、日志和停止入口。验收：项目切换不串配置，断线后能区分运行状态未知与已退出。
3. **Git 交付与隔离**：先实现选择性暂存、提交预览与补丁导出，再接入 PR 和 worktree。验收：只处理用户选择的改动，明确目标仓库/分支，支持错误恢复，不自动提交混合修改。
4. **能力感知**：维护有证据的接口能力表，区分版本不支持、账户条件、策略约束和暂时故障。实验性接口及插件市场不作为稳定路径的依赖。

### 第二阶段执行安排

用户已要求继续完成以上四项。继续使用 GPT-6.1 Sol 子代理：交付面板与能力面板、项目空间及进程管理、Git/PR/worktree 分工实现；主代理负责 RPC 能力证据和超时管理、模板入口、跨面板集成及总体验证。

- 所有写操作必须有实际可审阅 UI：提交预览明确暂存清单和分支，工作树与 PR 操作由用户点击触发，不在实施时操作本仓库或真实远端。
- 命令使用稳定 `command/exec` 与连接级进程标识，停止使用 `command/exec/terminate`；不以实验性无沙箱进程接口替代。不确定结果不自动重试。

- 使用单测、临时 Git 仓库测试和独立浏览器回归覆盖；不进行真实 PR 创建、推送或模型推理。
