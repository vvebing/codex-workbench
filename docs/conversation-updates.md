# 会话动态更新与渲染规则

本文记录当前实现，核对日期：2026-10-23。设计依据为会话 `01a162e7-b2a8-7340-b1c8-6d4dd5e07865`、`01a163ae-a91c-7132-8aba-899225a52a7e` 关于分组、双层展开、入场跳动和嵌套滚动的反馈。范围为会话正文、执行过程、交互卡片与阅读位置。

体验目标是内容连续、阅读位置稳定、操作立即响应。保留已有分组与阅读规则，动画只负责解释正在发生的变化，不通过延迟输出制造打字效果。

**1. 当前动画效果**

动画按变化来源区分：历史首次呈现保持静态，手动展开与收起始终有轻量过渡，执行期新增内容和输出增长平滑衔接。手动交互不依赖轮次是否仍在执行。高度使用阻尼弹簧过渡；新内容淡入，收起内容淡出。文本按收到的数据更新，不额外制造逐字播放延迟。

| 场景                                                      | 当前效果                                                                 |
| --------------------------------------------------------- | ------------------------------------------------------------------------ |
| 实时新增执行内容、助手进展或回答、首次出现的过程入口      | 从零高度展开，内容约 180 ms 淡入；文件修改及已知瞬时操作除外             |
| 流式文本、日志继续增长                                    | 高度变化时平滑调整；同一行追加文字且高度不变时，不重启动画，也不重复淡入 |
| 手动展开详情、批次或整轮过程                              | 从当前可见高度展开，内容约 200 ms 淡入；执行中和已结束轮次采用相同规则   |
| 详情、批次或整轮过程收起                                  | 高度逐渐降到零，内容约 160 ms 淡出；收起完成后才移除内容                 |
| 动画中再次展开或收起                                      | 从当前显示高度继续，保留高度运动速度，不先跳回起点                       |
| 重新打开已出现过的过程                                    | 不重播首次入场，只播放本次展开过渡                                       |
| 首次加载、刷新、切换会话、加载已有历史                    | 直接呈现当前状态，不补播历史入场动画；之后收到的实时变化再按运行规则处理 |
| 结构化结果、进度记录、本轮变更的手动展开与收起            | 复用同一高度过渡；关闭动画完成后才卸载内容                               |
| 文件修改、耗时显示为 0.0 秒的操作、仅由这些操作组成的批次 | 自动更新和自动折叠直接完成；手动展开、收起仍有过渡                       |
| 系统启用“减少动态效果”                                    | 跳过高度和淡入淡出动画，保持同样的最终展示状态                           |

高度过渡随距离和当前速度自然收敛。展开期间继续收到文字、日志或图片尺寸变化时，从当前可见高度调整目标；达到最新自然高度后才结束，避免最后一帧突然补齐内容。淡入只在入场时播放一次。

运行时尚未知道最终耗时的任务，可能已经展开；如果后来收到的耗时显示为 0.0 秒，会取消仍在进行的自动动画并直接应用自动收起状态。用户已经接管的手动展开与收起不受这个耗时判断影响。已经播放过的入场无法事后撤回。

单项详情和批次负责自己的展开、收起；外层执行列表负责新增内容和输出增长。普通内部折叠不另起外层动画；手动收起过程后保留异常项、重新展开时恢复成功项，这类条目增减由外层平滑调整高度，即使内部批次同时折叠。外层已有的动画会连续跟随最新高度再结束，避免直接取消造成跳变。尺寸观察只在动画运行期间启用。收起中的内容立即停止接收焦点和交互，视觉上保留到过渡结束。

**2. 会话内容的归属**

会话按轮次和原始事件顺序展示。每轮包含用户消息、执行过程、助手回答，以及可选的错误提示、本轮变更和轮次状态。

| 内容                           | 默认展示与过程归属                                                                         |
| ------------------------------ | ------------------------------------------------------------------------------------------ |
| 用户消息                       | 独立气泡，不随执行过程折叠；超出约 192 px 的长问题默认预览，可展开全文                     |
| 助手进展消息（commentary）     | 独立正文，属于执行过程；不会与相邻工具输出合并                                             |
| 最终回答（final_answer）       | 独立正文，不随执行过程折叠；旧数据没有阶段标记时，最后一条非 commentary 回答也保留在过程外 |
| 带结构化问题的助手消息         | 保留在过程外；回答表单由独立问题面板呈现                                                   |
| 空助手消息                     | 不渲染正文和额外空白；首段有效文字到达时再显示                                             |
| 轮次错误、状态、耗时、完成时间 | 独立显示，不随执行过程折叠；轮次结束后提供最终回答复制入口                                 |

发送中的本地用户消息会先显示发送状态，服务端确认后沿用稳定的展示身份，避免把同一条消息当成新气泡重新插入。用户消息支持文本、图片和引用；Markdown 正文支持代码、表格、图片和 Mermaid 等内容。

**3. 活动分类与合并**

| 活动                                             | 自动展示                                                   | 合并规则                                                                 |
| ------------------------------------------------ | ---------------------------------------------------------- | ------------------------------------------------------------------------ |
| 普通执行命令                                     | 运行时自动展开日志，已展开的日志通常保留到阶段结束         | 相邻普通命令归入同一批                                                   |
| 读取文件、浏览目录                               | 默认紧凑，详情按需展开                                     | 相邻读取与目录浏览归入读取批次                                           |
| 文件内容搜索                                     | 默认紧凑，详情按需展开                                     | 相邻搜索归入搜索批次，与读取分开                                         |
| MCP、动态工具调用                                | 运行时自动展开                                             | 仅相邻、同服务端或命名空间、同名工具合并                                 |
| 网页搜索                                         | 默认紧凑，按需查看                                         | 相邻网页搜索合并                                                         |
| 文件修改                                         | 默认收起，不播放自动入场；手动查看差异有展开过渡           | 相邻修改合并，文件数按路径去重，多次修改另外标注次数，每次原始差异仍保留 |
| 思考                                             | 执行中无摘要时显示“正在思考”；有内容时自动展开；结束后收起 | 独立记录；结束后仍为空则移除，但继续作为前后批次的边界                   |
| 计划、协作、子代理活动、图片生成                 | 执行中可自动展开，结束后按操作状态收起                     | 各自独立，不混入普通命令或工具批次                                       |
| 查看图片、等待、上下文整理、审查、其他已记录事件 | 独立紧凑记录，按需查看                                     | 不跨事件与相邻命令合并                                                   |

命令分类依据服务端的结构化操作信息：明确只有一个读取、目录浏览或搜索动作时采用相应分类；多个动作或无法识别的命令按普通执行命令处理。标题优先展示操作描述，完整命令和输出放在详情中。

只合并相邻活动，不跨越进展消息、思考、计划或其他类别。批次从第一项开始就有稳定身份，不因数量增加、完成或失败而替换；历史与实时记录采用同样的分组规则，不额外截成“最后几项”。

工具详情区分参数、返回结果和错误。MCP、动态工具与函数返回结果共用文本和媒体展示；协作报告、代码审查也支持 Markdown。JSON 对象与数组自动缩进、高亮，遇到非安全整数等数值时保留原始 JSON 文本；明确声明为纯文本、HTML 或代码等资源保留原文，避免 Markdown 改写。图片、音频和资源链接保留预览，本地图片复用文件读取预览。网页搜索展示查询、打开或查找动作以及返回数据，图片生成失败显示具体原因。

已有文本结果时，附加的结构化结果默认收起，展开后才渲染；仅有结构化结果时直接展示。等待、失败和完成但无返回内容分别提示。长输出限制在内部滚动区域，超大文本跳过高亮以保持响应；命令日志与 diff 保留等宽原文。复制时才组装完整输出，保留错误同时返回的部分结果及隐藏的结构化数据。

**4. 三层折叠分别控制什么**

| 层级         | 控制范围                                                 | 入口规则                                                                 |
| ------------ | -------------------------------------------------------- | ------------------------------------------------------------------------ |
| 单项详情     | 一条命令的日志、一次修改的差异、一次工具调用的参数和结果 | 点击具体操作标题查看                                                     |
| 同类批次     | 同一批中的操作条目                                       | 只有一项可见活动时隐藏批次入口，直接展示具体操作；至少两项才出现汇总入口 |
| 整轮执行过程 | 本轮进展消息与活动记录                                   | 有可展示的过程内容时，入口出现在第一段过程之前                           |

单项操作只需点击一次即可查看详情。多项批次收起后，先展开批次看到操作列表，再按需展开某项详情。从一项增加为多项时保留原节点、展开选择和已显示内容，已有条目的横向位置和宽度保持不变。收起过程后，一个批次只剩一项异常时，也只显示该操作本身。

**5. 自动收起的时机**

- 普通命令和同名工具调用按阶段处理。正在执行的批次保持展开；当前阶段中的命令间隔不会启动自动收起计时器。
- 一条命令结束后，如果它的日志曾自动展开、该阶段仍在进行且不是瞬时操作，日志继续保留。单条命令结束不等于整个阶段结束。
- 出现下一类活动或进展消息，且本批所有操作已经结束，才自动收起这一批。后续内容已经出现，但批内仍有并行操作运行时，继续等待。
- 整轮结束时，自动展开的批次和详情结束自动保持。手动展开优先，0.0 秒日志仍按瞬时规则处理。
- 默认仅在轮次成功完成时自动收起整轮过程；失败或中断不会因为轮次结束而自动隐藏整轮过程。用户手动选择收起的状态仍然有效。
- “完成后自动收起执行过程”设置只控制整轮过程，不关闭单项和批次自身的阶段收起规则。
- 首次打开历史时，已经完成的批次不会因为恰好排在当前运行轮的末尾就被重新自动展开；新的实际活动到来后才重新判断当前阶段。

例：命令 A 开始并展开 → A 完成，保持日志 → 命令 B 加入同批，继续展开 → B 完成，仍保持 → 出现下一段进展文字，本批已全部结束，才收起。如果用户已经手动展开日志，则继续保留该阅读选择。

**6. 手动阅读优先级**

手动选择优先于自动展开与自动收起。手动收起后，后续日志更新不会擅自打开；手动展开后，阶段结束也不会自动关闭该详情。

在已经展开的执行过程中，展开某项详情、点击详情内容选择或复制、把键盘焦点移入详情控件，会保留该项、所在批次和整轮过程。展开批次会保留批次与整轮过程。仅把鼠标移入或滚动日志，不等同于主动固定展开状态。

收起整轮过程优先隐藏过程内容，但保留内部选择，下次展开可继续查看。收起状态下查看异常详情，只改变该条目和批次的阅读选择，不会连带展开整轮过程。

阅读选择和会话滚动位置按环境、会话在当前页面运行期间缓存，切走再返回会尽量恢复。该缓存有容量限制，不承诺刷新页面后保留所有手动展开状态；自动收起偏好则保存在浏览器设置中。长用户问题和“本轮变更”的展开状态是各自的局部状态，不属于这份执行过程阅读缓存。

**7. 异常与待确认**

“需关注”包含失败、拒绝、中断、等待确认，按实际条目数量计数，不按批次数量计数。

- 整轮过程展开时显示完整过程，批次标注其中有多少项需关注。
- 整轮过程收起时，只显示需关注条目，同批次内成功的操作也隐藏。过滤保留原有批次边界和身份，不把原本不相邻的异常重新拼成一批。
- 展开异常批次或单项日志，不触发“展开执行过程”。只有主动展开整轮过程才恢复全部过程内容。
- 失败本身不会强制展开日志；已经展开的内容继续遵循阶段和手动阅读规则。等待确认的活动可以自动展开，文件修改的差异仍需手动查看。审批按钮位于独立审批区域。
- 每项操作按自己的结果显示状态；整轮后来失败，不会把已经成功完成的所有操作都标记为失败。

**8. 滚动与阅读位置**

| 场景                                                     | 会话行为                                                                     |
| -------------------------------------------------------- | ---------------------------------------------------------------------------- |
| 正在底部跟随，新内容增长或任务折叠                       | 同步保持在最新内容底部，不因布局缩短误判为主动上翻                           |
| 主动上翻会话，且会话实际离开底部                         | 暂停自动跟随，显示“回到底部”                                                 |
| 在任务日志、工具进度或内部代码区域滚动                   | 优先滚动内部内容；外层会话没有移动，就不触发“回到底部”                       |
| 日志到达边缘且允许滚动接力                               | 滚动可以传递给会话；只有会话实际上移离开底部，才退出跟随                     |
| 工具进度等限制滚动接力的区域到达边缘，或内部控件拦截输入 | 保持会话状态，不因收到向上输入而显示按钮                                     |
| 内容不足一屏                                             | 保持跟随、不显示按钮；后来内容增长，继续跟随最新内容                         |
| 已在阅读旧内容，其他任务增减高度                         | 尽量保持正在看的消息在屏幕原位置；该条目消失时，使用后续仍存在的内容作为参照 |
| 点击“回到底部”或手动滚到会话底部                         | 恢复自动跟随                                                                 |
| 点击问题导航圆点                                         | 跳到对应问题，保留返回原阅读位置的能力；这属于明确的应用内导航               |

布局变化前捕获阅读位置，尺寸变化后校正底部或阅读参照；同一帧先增长后折叠、最终总高度不变时，也会补一次位置校正。不会只凭滚轮、触摸或键盘向上输入就暂停跟随。

**9. 其他区域与当前动画边界**

- “本轮变更”仅在有文件变更记录或非空 diff 时出现，默认折叠，独立于执行过程，手动展开收起复用详情动画。展开后选择文件查看差异；操作记录行数是累计值，不等于最终净变更。
- 问题和审批面板独立于执行过程。异步回答可靠保存到本地队列后，立即以用户消息进入会话；排队、发送、失败恢复和待核实状态在消息下方显示，服务端消息到达后保留同一消息身份。问题失效时保留未发送的回答供复制。工具提问成功发送响应后，在所属轮次保留脱敏回答记录，服务端确认后原位更新；这类摘要仅保存在当前页面内存。保存或发送失败时保留原表单和填写内容。问题卡片在提交后用 200 ms 高度递减和淡出移除，包含外边距；减少动态效果模式直接移除。焦点转到回答记录，避免唤起移动端键盘。
- 问答提交期间可能保留卡片高度和焦点，减少控件替换引起的位置变化；这不是任务列表的弹簧收起动画。
- 用户气泡出现、长问题展开／收起、问题和审批卡片增删、状态文案变化，目前没有统一套用执行区的高度动画。这些区域仍按各自状态直接更新。
- 无会话、空会话、加载中分别展示对应提示；加载旧历史不会逐条补播入场。
