# 运行时性能

性能约束围绕连续输出、阅读位置和资源隔离设计。构建资源与加载策略见[构建与加载](bundle-performance.md)，会话交互规则见[会话呈现规则](conversation-updates.md)。

## 会话与历史

已有正文在切换回会话时直接显示，历史校验在后台进行。分页读取最近的历史窗口，用户按需加载更早内容；导出走完整历史读取路径。切换会话不保留整棵历史 DOM，阅读锚点与过程展开选择由轻量缓存恢复。

流式状态更新与订阅发布分开处理，增量发布合并到动画帧，终态及时发布。消息、Markdown、输入器与侧栏采用稳定渲染边界，计时器限制在耗时显示组件。折叠的执行详情按需挂载。

[`history-cache.ts`](../src/features/sessions/history-cache.ts) 使用默认 20 个会话、约 32 MiB 序列化估算的软预算，在导航边界淘汰冷正文。当前会话、运行中或可编辑会话、草稿、临时会话、未读和待处理交互受保护，可以超过预算。淘汰保留列表元数据，再次访问时读取正文。

阅读缓存默认保留 100 个会话。这是当前页面内存状态，刷新不保证保留；会话草稿与文件恢复存储另有独立的持久化流程。

## 文件与 Git

文件读取按文档合并在途请求；监听、焦点和手动刷新合并补读。内容不变时避免重复解码和发布，同时保留失败恢复与保存前冲突检查。

文件的轮询兜底周期为：前台活动普通文件 5 秒，其他可见文件或大文件 30 秒，隐藏面板或后台环境 60 秒；页面隐藏时暂停。监听和页面恢复用于补充及时性，不以短周期全量读取代替监听。

文件树按工作目录缓存数据和交互状态。Git 使用 `git rev-parse --show-toplevel` 确认工作树身份，同一工作树子目录共享状态，不同 worktree 和子模块保持隔离。Git 非活跃工作区缓存限制为 32 个。

项目身份用于界面标签和编辑器可见性；文件与 Git 缓存使用各自资源身份。所有缓存按环境与连接作用域隔离，不以路径前缀猜测项目归属。

## 大文件与恢复

[`file-limits.ts`](../src/features/files/file-limits.ts) 定义文件和差异默认限制。大文件采用简化模式，关闭高成本语法和自动标记功能；显式 diff 使用有界计算，超时有可见提示。

较大的编辑草稿通过 IndexedDB 异步恢复存储保存，界面展示保存状态。恢复副本不自动写回磁盘，也不能代替用户保存文件。存储不可用或容量不足应显示提示。

## 验证方式

单元测试覆盖单飞请求、失效合并、缓存保护、分页顺序、连接竞态、编辑冲突和增量发布；浏览器测试覆盖会话切换阅读位置、嵌套滚动、展开状态、流式更新与文件工作区。

```sh
npm run test:unit
npm run test:integration
npm run build
E2E_PRODUCTION=1 npm run test:e2e
```

行为测试不等同于硬件上的帧率、内存峰值或吞吐量测量。性能评估应记录构建版本、设备、会话规模与实际采样条件，避免把缓存命中或静态包大小直接当作端到端延迟。
