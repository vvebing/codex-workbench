# 性能优化实施记录

本次按 `performance-audit-2026-10-19.md` 实施运行时优化，不改变协议生成文件。

## 用户可感知的变化

- 已有内容的会话切回立即显示，新建、激活或分叉不再因历史校验标记失效而遮住正文。只读会话在后台刷新，失败保留内容并显示提示。
- 分页历史首次读取最近 30 轮，可点击“加载更早对话”；导出仍读取完整历史。旧格式历史保持兼容。
- 按环境作用域和会话保存阅读锚点、跟随底部和过程展开状态，切换时不保留整棵历史 DOM。
- 同工作目录的会话共享文件树数据与展开、选中、查询、滚动状态。文件/Git 标签切换不再从空目录开始。
- Git 刷新失败保留上次结果；Markdown 表格重渲染不再重建滚动容器。

## 渲染与请求控制

- 高频 delta 的状态同步更新，订阅发布按帧合并，最多 50ms 回退；完成等非增量事件立即发布，Node 环境保持同步。
- Markdown、消息、工具正文、Composer 与 Sidebar 建立稳定渲染边界。计时器下沉到耗时显示；折叠执行过程按需挂载。导航和输入器采用字段选择订阅，后台正文不再发布全局环境变化。
- 滚动按帧处理，二分查找附近轮次，只保存附近少量锚点。历史 item 合并改用 Map/Set，避免嵌套线性查找。
- 每个文件最多一个在途读取；watch、手动刷新和焦点变化合并补读，普通轮询不制造补读。内容相同避免解码与发布，但正确处理失败恢复和脏草稿撤销。
- 文件轮询：可见活动文件 5 秒、非活动文件 30 秒、隐藏面板或后台环境 60 秒；页面隐藏暂停，恢复时校验。保存仍执行冲突检查。
- Git 失效由共享 store 处理，按 revision、路径和会话工作目录过滤并合并；缓存仓库根目录。不变的状态保持引用，基线依赖 index blob 与 HEAD，隐藏编辑器暂停基线订阅。
- 文件树增加焦点与低频兜底；挂载间漏掉的文件 revision 会补校验，首次挂载不重复读取根目录。

## 缓存与时序约束

### 右侧栏的项目与工作区身份

项目级标签选择优先使用 app-server 的 `Thread.projectId`，缺失时回退到会话 `cwd`，并按环境与连接作用域隔离。侧栏宽度继续使用已有全局偏好。`thread/project/updated` 用于同步归属变化；项目可以包含多个根目录，因此项目身份不作为文件或 Git 数据的缓存键。

文件树继续按工作目录保存数据和交互状态。Git 通过 `git rev-parse --show-toplevel` 解析实际工作树根目录，再共享状态、刷新和订阅：同工作树中的不同子目录复用数据，不同 worktree 和子模块保持隔离。首次遇到新目录仍需解析其身份；不根据路径前缀、远程仓库地址或历史分支信息猜测归属。

Git 树/列表偏好、展开和选择状态按工作树保存；会话工具按会话隔离。缓存展示期间仍接收变化并后台校验，避免“保持状态”变成展示过期内容。这些交互缓存保留于当前页面内存，不新增磁盘持久化。

编辑器显示状态同样遵循项目身份：同项目切换会话保持当前编辑器、文件草稿与撤销记录；手动返回会话后不会因导航自动打开。跨项目或环境切换隐藏编辑器，但不丢弃已有草稿。目标会话元数据尚未加载时等待身份确认，避免同项目切换时先隐藏再恢复。

新增浏览器回归 5 项通过，覆盖项目标签与归属变化、会话滚动隔离和 Git 交互状态恢复；生产构建的 Git/目录相关回归 8 项通过。单元测试额外覆盖工作树共享与隔离、路径别名、连接竞态以及项目通知与读取响应的先后顺序。

会话正文默认按 20 个会话、约 32 MiB 的保守序列化估算执行软预算，在导航边界清理冷数据。当前会话、在途操作、运行中/可编辑会话、草稿、临时会话、未读和待处理交互受保护，允许超过预算。驱逐保留会话列表元数据，重访重新读取；不在每个 token 更新时执行容量清理。

阅读状态缓存最多 100 个会话，每会话最多 2000 个展开选择；目录缓存限制为 24 个工作区、每工作区 256 个目录（活跃订阅和展开目录受保护）；Git 缓存限制为 32 个非活跃工作区。正文不新增磁盘持久化。

缓存身份使用环境/连接作用域与资源身份隔离，epoch 用来拒绝旧连接响应。重连保留历史分页信息并重置加载状态，通过增量读取直到旧锚点连接新尾部，避免无重叠窗口拼接错序。缺少分页完整性信息的已有片段，首次校验回退为完整历史读取。

回滚推进历史版本并清除旧分页信息，明确截断被撤销的轮次；迟到页面不能复活旧消息。“加载更早”会等待后台同步，不会因为复用请求锁而吞掉用户点击。后台错误不会覆盖已切换到的其他会话错误状态。

## 验证

单元测试覆盖单飞、失效合并、无变化发布、读取恢复、编辑冲突、缓存容量保护、分页顺序、重连锚点、后台读取期间加载更早、delta 发布和终态抢先。

新增浏览器回归覆盖：A→B→A 阅读位置、旧 DOM 已卸载、表格节点与横向位置保持、同目录文件树展开保持，以及通过实际组件调用计数确认流式正文增长时 Composer 和 Sidebar 不重复渲染。

首轮验证结果：单元测试 505 项、集成测试 18 项通过；仓库检查、TypeScript、ESLint、格式检查与生产构建通过。浏览器全量初跑为 158 项通过、10 项失败、1 项跳过；失败项涉及滚动回归、Markdown 预览容器、Git fixture，以及并行测试产物和开发热更新干扰，均已修复或在独立服务复验通过。另有新增性能回归与相关滚动用例通过；最终未再次完整运行全部浏览器用例。

上述行为测试不等同于生产硬件上的帧率、内存峰值或吞吐量压测；暂不引入复杂虚拟列表，后续可根据真实长会话采样决定。生产构建仍提示部分资源超过 500 kB，资源体积优化不属于本轮运行时优化的完成范围。
